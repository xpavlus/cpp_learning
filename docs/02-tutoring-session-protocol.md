# 02 — Протокол учебной сессии с репетитором

Этот документ фиксирует алгоритм работы с AI-репетитором в рамках репозитория.

Цель протокола — сделать обучение последовательным: не просто получать готовые решения, а проверять понимание, закреплять навыки и сохранять прогресс в git.

## Базовый сценарий

1. Создать новую сессию с репетитором.
2. Указать тему урока и режим работы.
3. Попросить сформировать файлы урока.
4. Изучить подготовленные материалы и провести собственное исследование.
5. Ответить на вопросы из чеклиста своими словами.
6. При необходимости решить практическое задание.
7. Попросить репетитора проверить понимание без раскрытия правильных ответов.
8. Исправить пробелы через дополнительные вопросы, объяснения и упражнения.
9. Если тема все еще не усвоена, попросить отдельный закрепляющий урок.
10. В конце зафиксировать итог урока.

## Стартовый запрос

В начале новой сессии удобно явно задать режим:

```text
Режим: репетитор.
Тема: lesson/NN-topic-name.
Не давай готовые ответы, пока я явно не попрошу.
Проверяй понимание через вопросы и маленькие задачи.
Если видишь пробел, дай дополнительное упражнение.
```

Если нужно подготовить новый урок:

```text
Сформируй файлы урока для темы lesson/NN-topic-name:
- notes.md
- checklist.md
- src/task01.cpp
- tutor.md

Не делай готовое решение задания.
```

## Рекомендуемые файлы урока

Каждый урок лучше вести в одинаковой структуре:

```text
lessons/NN_topic/
├── notes.md
├── checklist.md
├── tutor.md
└── src/
    └── task01.cpp
```

Назначение файлов:

| Файл | Назначение |
|------|------------|
| `notes.md` | Краткая теория, примеры, основные термины |
| `checklist.md` | Вопросы и навыки для самопроверки |
| `tutor.md` | Цели урока, критерии завершения, дополнительные упражнения, замечания репетитора |
| `src/task01.cpp` | Практическое задание без готового решения |

## Роли

### Ученик

Ученик:

- читает материалы урока;
- ищет дополнительные объяснения самостоятельно;
- отвечает на чеклист своими словами;
- пишет код сам;
- просит подсказку, если застрял;
- исправляет замечания после ревью;
- фиксирует итоги урока.

### Репетитор

Репетитор:

- готовит структуру урока;
- объясняет тему на нужном уровне;
- задает проверочные вопросы;
- оценивает полноту понимания;
- не раскрывает правильные ответы сразу;
- делает ревью кода;
- дает дополнительные упражнения при пробелах;
- помогает решить проблему, если ученик застрял после нескольких итераций.

## Проверка понимания

Проверка понимания проводится до или параллельно с проверкой кода.

Хороший запрос:

```text
Я ответил на checklist своими словами.
Оцени, где неполно или неточно, но не давай правильный ответ сразу.
Задай уточняющие вопросы.
```

Репетитор должен оценивать:

- точность терминов;
- понимание причин, а не только синтаксиса;
- способность объяснить тему простыми словами;
- способность применить тему в новой ситуации;
- типичные заблуждения.

## Проверка кода

Код проверяется отдельно от теории.

Хороший запрос:

```text
Сделай ревью task01 как репетитор.
Укажи ошибки и подсказки, но не исправляй код сам.
```

Во время ревью репетитор смотрит:

- собирается ли код;
- соответствует ли решение заданию;
- корректно ли обработаны крайние случаи;
- используются ли конструкции текущей темы;
- понятны ли имена;
- нет ли лишнего усложнения;
- можно ли улучшить стиль без переписывания всего решения.

## Уровни помощи

Чтобы обучение не превращалось в копирование готового ответа, помощь дается по уровням.

1. Наводящий вопрос.
2. Подсказка по направлению.
3. Указание на конкретную ошибку.
4. Маленький пример отдельно от задания.
5. Частичный фрагмент решения.
6. Полное решение только по явной просьбе или после нескольких неудачных итераций.

Пример запроса на мягкую помощь:

```text
Я застрял, но не давай решение.
Дай только подсказку, куда смотреть.
```

Пример запроса на более прямую помощь:

```text
Я попробовал несколько вариантов и все еще не понимаю.
Разбери ошибку подробнее и покажи маленький отдельный пример.
```

## Когда нужен закрепляющий урок

Отдельный закрепляющий урок нужен, если после нескольких итераций остаются устойчивые пробелы.

Признаки:

- ученик не может объяснить решение своими словами;
- одна и та же ошибка повторяется в разных заданиях;
- код работает случайно, без понимания причины;
- тема требует слишком много подсказок;
- новая задача на ту же тему вызывает полную остановку.

Закрепляющий урок должен быть уже основного урока и фокусироваться на одном слабом месте.

Пример:

```text
Сформируй отдельный закрепляющий урок по const references.
Мне сложно понять, когда передавать по значению, а когда по const&.
```

## Итог урока

В конце темы нужно зафиксировать результат.

Итог можно записывать в `LEARNING_LOG.md` или в `tutor.md` конкретного урока.

Шаблон:

```md
## Итог урока

Тема: lesson/NN-topic-name

Понимаю:
- ...
- ...

Нужно повторить:
- ...
- ...

Решено:
- task01
- task02

Замечания после ревью:
- ...
- ...

Статус:
- тема закрыта / нужна повторная практика
```

## Git-процесс

На каждый урок лучше создавать отдельную ветку:

```powershell
git checkout -b lesson/NN-topic-name
```

Во время работы:

```powershell
git status
git diff
```

После первого решения:

```powershell
git add lessons/NN_topic
git commit -m "lesson NN: complete task01"
```

После исправлений по ревью:

```powershell
git add lessons/NN_topic
git commit -m "lesson NN: address review comments"
```

## Критерии завершения темы

Тема считается закрытой, если:

- материалы урока прочитаны;
- чеклист разобран своими словами;
- практические задания решены;
- код собирается;
- замечания ревью исправлены;
- ученик может объяснить ключевые решения;
- есть итоговая запись;
- тема применена хотя бы в одной маленькой новой задаче.

Важно: тема не считается усвоенной только потому, что код работает.

Сначала проверяется понимание, затем код, затем применение в новой ситуации.
